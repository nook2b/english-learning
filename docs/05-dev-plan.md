# План разработки (версия 2)

> Обновлён 29.10.2026 после ревизии документов. Что поменялось и почему — в [`06-review.md`](06-review.md).

Делаем **вертикальными срезами**: после каждого этапа есть что открыть и потрогать. Арт и сюжет до готовности заменяются заглушками.

**Кто что делает**: я пишу сеттинг и сюжет и генерирую арт. Claude пишет код и учебный контент (по [`04-curriculum.md`](04-curriculum.md)) и верстает сюжет в Ink.

## Принципы

1. **Пользоваться как можно раньше.** Приложение стоит на телефоне с этапа 1, учиться по нему я начинаю с этапа 3. То, что мешает ежедневному использованию (потеря прогресса, нет напоминаний), делаем раньше украшений.
2. **Контент — главный объём работы.** Только на арку 1 нужно около 45 уроков, 400–500 слов, 100 неправильных глаголов, 300–400 грамматических предложений и 7 глав. Поэтому конвейер контента с проверками строим сразу, а юниты готовим на 1–2 вперёд моего прохождения, начиная с самых слабых тем по карте времён.
3. **Ошибка в контенте хуже, чем отсутствие контента.** На B1 я не замечу неверный «правильный» ответ и выучу ошибку. Каждое задание проходит автоматическую проверку и отдельную проверку на однозначность.
4. **Сюжет не блокирует код.** Этапам 1–6 сюжет не нужен. Пролог и глава 1 нужны к началу этапа 7.

## Стек

| Задача | Технология |
|---|---|
| Монорепозиторий | pnpm workspaces |
| Приложение | React + TypeScript + Vite, PWA (vite-plugin-pwa) |
| Состояние и хранение | Zustand, Dexie (IndexedDB) |
| Повторения | ts-fsrs |
| Сюжет | Ink + inkjs, компиляция в JSON при сборке |
| Telegram | Mini App (`telegram-web-app.js` или `@telegram-apps/sdk`), бот на grammY через вебхук |
| Сервер | Один Cloudflare Worker: статические ассеты + API + вебхук бота + Cron Triggers; база D1 |
| Озвучка | Скрипт генерирует аудио через TTS при подготовке контента, файлы лежат рядом со статикой |
| Проверка контента | zod-схемы + скрипт `content:check` |
| Тесты и CI | Vitest, Playwright, GitHub Actions |

## Форматы контента (примеры)

Упражнение с выбором:

```json
{
  "id": "u01-l03-e05",
  "type": "tense_choice",
  "prompt": "Look! It ___ outside.",
  "options": ["rains", "is raining"],
  "answers": ["is raining"],
  "mistakes": { "rains": "pres_simple_for_now" },
  "explain": "Look! — действие происходит прямо сейчас → Present Continuous.",
  "topics": ["pres_cont", "pres_simple"]
}
```

Упражнение с вводом: несколько верных ответов и распознавание типичных ошибок:

```json
{
  "id": "u06-l05-e02",
  "type": "translate",
  "prompt": "Я живу здесь с 2020 года.",
  "answers": ["I have lived here since 2020.", "I have been living here since 2020."],
  "mistakes": {
    "I live here since 2020.": "present_for_period",
    "I am living here since 2020.": "present_for_period"
  },
  "explain": "«С 2020 года и до сих пор» — период до настоящего момента → Present Perfect или Present Perfect Continuous.",
  "topics": ["pres_perf", "pres_perf_cont"]
}
```

- `answers` — всегда список: верных вариантов бывает несколько. Ответ сравнивается после нормализации: сокращения (I've = I have), регистр, пунктуация, апострофы.
- `mistakes` связывает известный неверный ответ с тегом ошибки из `content/tags.json`. По тегу показывается точное объяснение и подбирается повторение.
- `topics` — коды тем из [`04-curriculum.md`](04-curriculum.md), раздел 5.

Сцена в Ink с выбором-упражнением (пример проверен компилятором inkjs 2.4):

```ink
=== ch01_rei_intro ===
Rei: So you're the new member? What did you do before you came here? #rei:pout
* [I studied in Moscow. #correct]
    ~ affection_rei += 2
    Rei: Hmph. Not bad. #rei:blush
* [I have studied in Moscow two years ago. #mistake:pres_perf_with_past_time]
    Rei: "Have studied... ago"? Seriously? #rei:smug
* [I was study in Moscow. #mistake:be_plus_verb]
    Rei: Iris is going to cry. #rei:smug
- Rei: Anyway. Practice starts at five. Don't be late. #rei:neutral
-> DONE
```

Соглашения для сюжета:
- Теги варианта пишутся **внутри квадратных скобок**. Тогда они попадают в `choice.tags`, и движок видит их до выбора: может перемешать варианты и знает, какой ошибочный. Тег после `]` всплывает только после выбора, отдельной пустой строкой.
- `#correct` — верный вариант, `#mistake:<тег>` — неверный, тег берётся из `content/tags.json`. После сцены Айрис объясняет ошибку, а предложение уходит в повторение.
- `#<героиня>:<эмоция>` — спрайт для реплики. Эмоции из списка в [`03-plan.md`](03-plan.md), раздел 5.
- `Имя: текст` — реплика героини, строка без имени — текст рассказчика.
- После вариантов идёт общая ветка (`-`) или переход (`->`), иначе сцена обрывается.
- Переменные привязанности (`VAR affection_rei = 0` и т. д.) объявляются один раз в `story/main.ink`. Источник истины — приложение: перед сценой оно записывает в Ink текущие значения, после сцены сохраняет изменения у себя. Так привязанность от учёбы (стрик, точность, дуэль) и от выборов в сценах не расходится.

## Этапы

### Этап 1. Каркас и деплой
- [ ] pnpm-монорепозиторий: `app`, `server`, `shared`, `tools`
- [ ] Vite + React + TS, ESLint, Prettier, Vitest
- [ ] CI в GitHub Actions: линтер, типы, тесты
- [ ] Экраны-заглушки: Путь, Урок, Повторение, История, Профиль
- [ ] Хранилище прогресса (Dexie) + экспорт и импорт прогресса в JSON-файл
- [ ] Базовый UI-кит: кнопки, карточки, прогресс-бар, окно реплики героини
- [ ] PWA: манифест, иконка, установка на телефон, офлайн-кэш оболочки
- [ ] Деплой на Cloudflare Workers (статика), автодеплой из основной ветки
- [ ] Арт-трек: выбрать модель, сделать референсы трёх героинь

**Готово, когда**: открываю ссылку на телефоне, ставлю приложение на главный экран и вижу главный экран.

### Этап 2. Движок упражнений и диагностика
- [ ] zod-схемы контента в `shared/`, словарь тегов `content/tags.json`
- [ ] `content:check` в CI: схема, уникальные id, верный ответ есть среди вариантов, все теги есть в словаре
- [ ] Типы упражнений T1–T7
- [ ] Проверка ответов: нормализация, несколько верных вариантов, распознавание известных ошибок по `mistakes`
- [ ] Объяснение после ошибки, экран итогов урока, спрайт-заглушка Айрис
- [ ] Диагностика: около 50 заданий (10 тем арки 1 по 4 задания + словарь), можно в два захода
- [ ] Карта времён: освоено, шатко, не освоено

**Готово, когда**: прошёл диагностику и вижу, какие времена проседают. По карте решаем, какие юниты готовить первыми.

### Этап 3. Юнит 1, путь и конвейер контента
- [ ] Конвейер: Claude генерирует юнит → `content:check` → проверка однозначности (отдельный проход ищет второй верный ответ и спорные задания) → выборочная вычитка → коммит
- [ ] Кнопка «пожаловаться на задание»: задание помечается, список жалоб виден в профиле и выгружается, Claude разбирает их пачкой
- [ ] Скрипт озвучки: аудио для всех предложений, кэш по хэшу текста, у каждой героини свой голос. Проверить, есть ли у выбранного TTS голос en-AU для Рэй
- [ ] Тип упражнений T8 (диктант)
- [ ] Путь юнитов: блокировка, тест-аут по карте времён
- [ ] Контент юнита 1 (или самого слабого юнита по карте)

**Готово, когда**: прохожу учебные уроки 1–5 и чекпоинт юнита 1. Глава сюжета пока заглушка, она появится на этапе 7.

### Этап 4. Повторение (SRS)
- [ ] ts-fsrs с целевым запоминанием 90%, три колоды: слова, неправильные глаголы, грамматика
- [ ] Новые слова вводятся в сессии повторения с лимитом новых в день (по умолчанию 10). Типы T10–T12
- [ ] Грамматическая карточка — шаблон, предложения при повторах меняются
- [ ] Автодобавление: слова юнита и предложения с ошибками
- [ ] Работа над ошибками по тегам

**Готово, когда**: каждый день есть колода повторения, новые слова юнита попадают в неё сами, а ошибки из уроков в неё возвращаются. С этого момента учусь по приложению каждый день.

### Этап 5. Telegram и синхронизация
- [ ] Режим Mini App: тема Telegram, кнопка «назад», вход без регистрации
- [ ] Проверка подписи данных Telegram (initData) на сервере
- [ ] Вход в браузерной PWA: одноразовая ссылка от бота (команда `/login`)
- [ ] Worker API + D1: синхронизация между устройствами. Сервер — источник истины. Журнал ответов и повторений только дописывается, остальные данные сливаются по времени последнего изменения
- [ ] Бот: ежедневное напоминание от Мики в выбранное время с учётом часового пояса. После этапа 7 пишет героиня с самой высокой привязанностью

**Готово, когда**: открываю приложение из Telegram на телефоне и в браузере на компьютере, прогресс один и тот же, а вечером приходит сообщение от героини.

### Этап 6. Геймификация
- [ ] XP, кольцо дневной цели, стрик + заморозка
- [ ] Кристаллы, магазин (заморозки; подарки добавятся на этапе 7)
- [ ] Дневные квесты
- [ ] Недельная дуэль с Рэй (её XP подстраивается под мой темп, чтобы победа давалась с усилием)
- [ ] Бот: предупреждение «стрик под угрозой»
- [ ] Экран статистики: слова, точность, ошибки по тегам

**Готово, когда**: есть причина зайти завтра.

### Этап 7. Новелла и романтика
- [ ] Рендер сцены: фон, 1–2 спрайта с эмоциями, печать текста, лог, авто и пропуск
- [ ] Ink: `main.ink` с INCLUDE глав, компиляция при сборке, проверка компиляции в CI
- [ ] Привязанность хранится в приложении и передаётся в переменные Ink до сцены и обратно после
- [ ] Выборы-упражнения: теги внутри скобок, перемешивание вариантов, разбор ошибок от Айрис, ошибочные фразы — в повторение
- [ ] Перевод слова по тапу, кнопка «перевод реплики»
- [ ] Гейты: глава открывается после уроков 1–5 юнита, свидание — после чекпоинта и порога привязанности
- [ ] Подарки в магазине, экран отношений, галерея CG
- [ ] Пролог и глава 1 по моему сюжету

### Этап 8. Сюжет и арт арки 1

## Риски

| Риск | Что делаем |
|---|---|
| Ошибки в сгенерированном контенте | `content:check`, проверка однозначности, вычитка, кнопка жалобы, метрика «подтверждённых жалоб меньше 1%» |
| В Telegram на Android нет браузерного TTS | Аудиофайлы генерируем заранее, браузерный TTS — только запасной вариант |
| Хранилище WebView в Telegram очищается | До этапа 5 — экспорт в файл, с этапа 5 — сервер как источник истины |
| Нет подходящего TTS-голоса с австралийским акцентом для Рэй | Проверить на этапе 3. Запасной вариант — британский или американский голос |
| Модель маршрутов и признания не решена | Решить до этапа 7 ([`03-plan.md`](03-plan.md), раздел 8) |
| Сюжет не готов к этапу 7 | Этапы 1–6 от него не зависят, до готовности — заглушки |
| Героини на арте получаются неконсистентными | Начать арт-пайплайн на этапе 1, а не на этапе 8 |
| Приложение доступно по публичной ссылке | API работает только после авторизации, ссылку не публикую |
| Объём расползается | Всё, чего нет в чек-листах этапа, уходит в бэклог |
