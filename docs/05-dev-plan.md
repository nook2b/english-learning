# План разработки

Делаем **вертикальными срезами**: после каждого этапа есть что открыть и потрогать. Арт и сюжет до готовности заменяются заглушками. Ни один этап не опирается на то, что появится позже.

**Кто что делает**: ты пишешь сеттинг и сюжет. Код, учебный контент (по [`04-curriculum.md`](04-curriculum.md)) и вёрстку сюжета в Ink делаю я.

**Параллельность**: этапы 1–5 сюжета не требуют, их можно делать, пока ты пишешь. Этап 6 начинаем, когда готовы пролог и глава 1.

**Сразу закладываем второго ученика**: `user_id` во всех данных, теги навыков вместо «времён», каталог тем и построитель пути, гейты истории по числу пройденных юнитов, слоты-упражнения в сценах. Подробно — [`00-full-plan.md`](00-full-plan.md), раздел 5.

Если этот документ расходится с `00-full-plan.md`, верен `00`.

## Стек

| Задача | Технология |
|---|---|
| Приложение | React + TypeScript + Vite, PWA (vite-plugin-pwa) |
| Состояние и хранение | Zustand, Dexie (IndexedDB) |
| Повторения | ts-fsrs |
| Сюжет | Ink + inkjs |
| Telegram | Telegram Mini App SDK, виджет «Войти через Telegram» для браузера, бот на grammY |
| Сервер | Cloudflare Workers + D1 + Cron, хостинг Cloudflare Pages |
| Проверка контента | zod (схемы JSON) + тесты контента |
| Озвучка | Аудиофайлы, заранее сгенерированные TTS-сервисом при сборке. Web Speech API — запасной вариант с проверкой доступности: в WebView Telegram на Android его часто нет |
| Тесты | Vitest, Playwright |

## Структура репозитория

```
app/                        # фронтенд
  src/
    features/lesson/        # движок упражнений
    features/placement/     # диагностика, карта навыков, построение пути
    features/srs/           # повторения
    features/story/         # рендер новеллы + Ink + слоты-упражнения
    features/game/          # XP, стрик, квесты, магазин, дуэль, неделя с Микой
    features/minigames/     # мини-игры
    data/                   # Dexie, синхронизация (всё с user_id)
    ui/                     # UI-кит
content/
  catalog.json              # каталог тем: уровень, зависимости
  units/                    # юниты по темам
  diagnostic/               # банк заданий диагностики
  errors/ru.json            # библиотека типичных ошибок по тегам
  words/, verbs/irregular.json
  story/*.ink, story/slots/*.json
  characters/*.json
assets/                     # спрайты, фоны, CG, аудио
server/                     # Cloudflare Worker: API, бот, cron
docs/
```

## Форматы контента

Примеры упражнения, юнита в каталоге и сцены со слотом-упражнением — в [`00-full-plan.md`](00-full-plan.md), раздел 7. Главное:

- В упражнении тип движка общий (`choice`, `gap_input`, `translate`...), а тема задаётся тегами навыков (`skills`).
- В сценах выбор-упражнение — это слот: Ink ставит тег `#exercise:<id>` на вариант выбора, а верные реплики и неверные варианты по тегам лежат в `story/slots/*.json`.
- Если выбор фиксированный, теги ставятся внутри квадратных скобок: `* [I was study in Moscow. #mistake:grammar.be_plus_verb]`. Тег после `]` к выбору не привязывается (проверено на inkjs 2.3.2).

## Этапы

### Этап 1. Каркас
- [ ] Vite + React + TS, линтер, тесты
- [ ] PWA: иконка, установка на телефон, офлайн
- [ ] Экраны-заглушки: Путь, Урок, Тренировка, История, Героини, Профиль
- [ ] Хранилище прогресса (Dexie), все данные с `user_id`, профиль ученика (имя, род, цель, дневная цель)
- [ ] Базовый UI-кит: кнопки, карточки, прогресс-бар, окно реплики героини
- [ ] Деплой превью на Cloudflare Pages

**Готово, когда**: открываю ссылку на телефоне и вижу главный экран.

### Этап 2. Движок упражнений + юнит 1
- [ ] Схема контента (JSON + zod): упражнения с тегами навыков, юниты, каталог тем
- [ ] Типы упражнений T1–T7, T9, T10, T11 (T8 — на этапе 6, когда будут аудиофайлы; T12 — вместе с историей)
- [ ] Проверка ответов: сокращения, регистр, пунктуация, несколько верных вариантов
- [ ] Экран итогов урока, разбор ошибок от Айрис (спрайт-заглушка), запись ошибок по тегам
- [ ] Тесты контента: у каждого упражнения есть ответ, варианты не повторяются, теги есть в словаре тегов
- [ ] Контент юнита 1 моего пути (Present Simple vs Present Continuous)

**Готово, когда**: можно пройти все уроки юнита 1.

### Этап 3. Диагностика и путь
- [ ] Банк заданий: общий блок по каталогу тем, углублённый блок по временам, оценка словаря; у каждого задания 3 варианта
- [ ] Карта навыков: освоено, шатко, не освоено
- [ ] Построение личного пути по каталогу и зависимостям, ручная правка пути
- [ ] Путь юнитов: блокировка, тест-аут, чекпоинты; «освоено по диагностике» считается пройденным для гейтов
- [ ] Контент юнитов 2 и 3

**Готово, когда**: после диагностики видно, какие темы проседают, и путь собрался из них. Проверка: пройти диагностику «за другого ученика» (времена без ошибок, ошибки в артиклях) — путь должен получиться другим.

### Этап 4. Повторение (SRS)
- [ ] ts-fsrs, три колоды: слова, неправильные глаголы, грамматические карточки
- [ ] Очередь новых карточек с приоритетами: ошибки (до 2 в день, по одной на тег) → глаголы текущего юнита → ключевые слова → слова из сюжета
- [ ] Лимит новых по дневной цели (3, 5, 8, 10), стоп новых при долге больше двух дневных норм
- [ ] Автооценка: Again, Hard, Good; Easy — только кнопкой
- [ ] Работа над ошибками по тегам, разные предложения на один тег

**Готово, когда**: каждый день есть колода повторения, ошибки из уроков в неё возвращаются, а на повторение уходит не больше половины дневной цели.

### Этап 5. Геймификация и первые мини-игры
- [ ] XP (урок 30, карточка 1, глава 20 и т. д.), кольцо дневной цели, стрик + заморозка, часовой пояс и конец дня
- [ ] Кристаллы, магазин (пока только заморозки)
- [ ] Дневные квесты, только выполнимые сегодня
- [ ] Недельная дуэль с Рэй: база — медиана моего XP за 3 недели в пределах от «цель × 7» до «цель × 7 × 1,5», множитель 1,05–1,15
- [ ] «Неделя с Микой»: цель 5 дней из 7
- [ ] Раздел «Тренировка», мини-игры M1 «Пары на скорость» и M2 «Блиц с Рэй»
- [ ] Экран статистики: слова, точность, карта навыков, ошибки по тегам, рекорды

**Готово, когда**: есть причина зайти завтра.

### Этап 6. Новелла и романтика
- [ ] Рендер сцены: фон, 1–2 спрайта с эмоциями, печать текста, лог, авто и пропуск
- [ ] Ink: компиляция при сборке, переменные привязанности для каждой героини
- [ ] Слоты-упражнения: подбор неверных вариантов под теги ученика, реакции, разбор ошибок от Айрис
- [ ] Вопросы на понимание после главы (T12)
- [ ] Перевод слова по тапу, кнопка «перевод реплики»
- [ ] Аудио: генерация TTS-файлов при сборке, проигрыватель, запасной браузерный синтез; диктант (T8)
- [ ] Гейты: глава открывается после очередного юнита пути, свидание — после юнита и порога привязанности
- [ ] Привязанность по таблице баланса, в том числе за дуэль, «неделю с Микой» и вехи стрика
- [ ] Экран «Героини», подарки в магазине (до 2 в неделю каждой, день рождения ×2), галерея CG, квесты на выборы в истории
- [ ] Пролог и глава 1 по твоему сюжету

**Готово, когда**: после юнита 1 открывается глава 1, а мои выборы меняют привязанность.

### Этап 7. Telegram и синхронизация
- [ ] Режим Mini App: тема Telegram, кнопка «назад», вход без регистрации
- [ ] Проверка подписи данных Telegram на сервере
- [ ] Вход через виджет Telegram в браузерной версии
- [ ] Worker API + D1: синхронизация прогресса по `user_id`, список разрешённых аккаунтов
- [ ] Бот: напоминание от героини с самой высокой привязанностью, «стрик под угрозой», итоги дуэли и «недели с Микой», новые сцены
- [ ] Мини-игра M3 «Переписка»: сообщение героини с выбором ответа кнопками

**Готово, когда**: открываю приложение из Telegram на телефоне и в браузере на компьютере, прогресс один и тот же, а вечером приходит сообщение от героини.

### Этап 8. Контент и арт арки 1
- [ ] Юниты 4–7 моего пути + экзамен арки
- [ ] Главы 2–7, свидания, выбор маршрута, кульминация, признание и дружеская версия
- [ ] Арт: 3 героини × 9 эмоций, 6–8 фонов, 5–10 CG
- [ ] Озвучка всех реплик

**Готово, когда**: арка 1 проходится от начала до признания.

### Этап 9 (v1.x). Больше игр и второй ученик
- [ ] Мини-игры M4–M9 (см. [`06-games.md`](06-games.md))
- [ ] Параметры героя, восстановление стрика, сезонные ивенты, достижения, итоги месяца
- [ ] Модули под второго ученика по его диагностике: LLM → проверка схемой и тестами → ручная вычитка

**Готово, когда**: второй человек сам проходит онбординг и диагностику и получает свой путь из готовых юнитов.
