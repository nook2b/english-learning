# English Club — E-mote: оценка и бриф на пробу (пролог)

Версия 1 · 01.11.2026. Вопрос: можно ли сделать анимацию героинь плавнее и «живее» на E-mote (M2 Co., https://emote.mtwo.co.jp/about/), может ли Claude работать с ним по API, и что подготовить для пробы на прологе.

## 1. Коротко

**Вывод: переходить на E-mote не рекомендую.** Эффект, ради которого его выбирают («оживлённая иллюстрация»: дыхание, поворот головы в 2.5D, волосы с физикой), мы уже закладываем в Rive в [брифе 27](27-full-rig-brief.md). Там же есть то, чего в E-mote нет или что в нём сложно: руки с IK, предметы, жесты, переходы между позами. У E-mote нет API, редактор работает только под Windows и только на японском, а веб-SDK не обновлялся с 2018 года. Если хотите проверить сами, ниже бриф на небольшую пробу (раздел 5), но в бюджете я бы закладывал её как сравнение, а не как переход.

## 2. Что такое E-mote

- Японский инструмент от M2 Co. для анимации 2D-иллюстраций: берёт многослойный PSD, раскладывает его по **готовому шаблону** (имена слоёв должны точно совпадать) и деформирует. Кости вручную не нужны. Внутри есть физика волос и груди, интерполяция выражений, управление взглядом.
- Направление: визуальные новеллы и мобильные гача-игры (живые портреты в диалогах). Это прямой аналог Live2D Cubism, только менее распространён.
- **Редакторы** (все только для Windows):
  - えもふり (Emofuri), бесплатный: PSD до 2048×2048, видео до 1024×1024. Коммерческое использование разрешено только физлицам и додзинси, компаниям — только как пробная версия.
  - E-mote MovieMaker: ¥90 000 в год, экспортирует видео.
  - Редактор + SDK по лицензии (ниже).
- **Форматы**: `.psd` на входе → проект `.emtproj` → рантайм-файл `.emtbytes`. На выходе также PNG-секвенции, GIF, WMV.
- **SDK**: DirectX, Unity, cocos2d-x/js, iOS, Android, PS4/Vita, **WebGL (HTML5 Native)**. На сайте лежит только демо-SDK (обновлён 06.07.2018), и он показывает только встроенных персонажей. Полный SDK выдаётся после заключения договора. Пакета в npm нет. Файлы не открываются из `file://`, нужен веб-сервер.
- **Лицензии**:
  - Indies, бесплатно: для компаний с выручкой до ¥10 млн в год и для физлиц. Один SDK под одну платформу и один редактор на год. Заявка — через японскую форму.
  - Commercial: ¥300 000 в год (без налога), 1 SDK и 1 редактор, логотип E-mote при старте обязателен.
  - Academic: ¥5 000, только для учащихся.
  - После окончания договора SDK и уже выпущенные `.emtbytes` продолжают работать, а редактировать в редакторе больше нельзя.
- **Поддержка**: только на японском, форма на сайте, ответ около 3 рабочих дней. Есть форум и студия, которая делает персонажей под заказ.

## 3. Может ли Claude работать с E-mote

| Что | Можно ли | Как |
|---|---|---|
| API / облачный сервис | **Нет** | У E-mote нет ни HTTP API, ни облака. Это локальный Windows-редактор плюс SDK для встраивания |
| Skills / плагины | **Нет** | Поиск по каталогу skills ничего не нашёл: готовых skills для E-mote, Live2D или Rive нет |
| Работа в редакторе | **Нет** | Редактор — GUI под Windows, а у меня Linux-контейнер в облаке |
| Подготовить PSD под шаблон | Частично | Могу проверить структуру и имена слоёв скриптом, собрать PSD из готовых PNG-слоёв, свериться с шаблоном E-mote |
| Встроить SDK в приложение | Да, когда будет SDK | Компонент `EmoteHeroine` рядом с `RiveHeroine` с тем же контрактом: expression, mouth, talking, look. Но только после того, как вы получите SDK по договору |
| Брифы, контент, разметка сцен | Да | Как сейчас: эмоции, взгляд, жесты по репликам, липсинк по разметке ElevenLabs |

Итог: анимирует в любом случае человек (аниматор в редакторе). От меня — подготовка, проверка арта, интеграция и управление из сюжета. Это так и с Rive, и с E-mote, и с Live2D.

## 4. Сравнение для нашего приложения

| | **Rive (сейчас + бриф 27)** | **E-mote** | Live2D Cubism (для справки) |
|---|---|---|---|
| Уже встроен в приложение | **Да**, `@rive-app/react-canvas`, `RiveHeroine.tsx` | Нет, писать с нуля | Нет |
| Веб-рантайм | Актуальный, в npm, WASM | WebGL SDK 2018 года, только по договору | Актуальный Web SDK |
| «Живая» голова в 2.5D, дыхание, волосы | Да (сетки и кости, запаздывание) | **Сильная сторона**, есть физика | Сильная сторона |
| Руки, предметы, жесты, IK | **Да** | Слабо: заточен под портрет | Ограниченно |
| Управление из кода (View Model, state machine) | Да, контракт уже есть | Через API SDK | Через параметры |
| Редактор | Браузер, любая ОС, английский | Windows, японский | Windows/Mac |
| Рынок аниматоров | Широкий, западный | Узкий, японский | Широкий |
| Цена | Подписка Rive | Бесплатно (Indies) или ¥300 000 в год | Бесплатно до порога выручки, дальше лицензия |
| Размер файла | Маленький | Маленький | Средний |

**Почему движение сейчас кажется недостаточно плавным:** дело не в движке. Комплект v14 — это плоские позы с подменой лица, голова неподвижна, рот в 3 кадра. Плавность дадут **сочленённый риг, поворот головы в 2.5D, вторичное движение волос, виземы и плавные переходы между позами**, то есть ровно этапы брифа 27. Это можно сделать в Rive, не меняя движок и контракт с приложением.

**Моя рекомендация:**
1. Запустить **этап 0 брифа 27** (Мика, полный риг) и принимать его на сцене пролога. Это главный рычаг качества.
2. Усилить ТЗ аниматору тем, что делает «японский» вид у E-mote и Live2D: деформация лица при повороте головы (а не сдвиг слоёв), физика волос, микродвижения в покое. Пункты добавил в раздел 6.
3. E-mote — только если после этапа 0 «живость» лица всё равно не устроит. Тогда пробу из раздела 5 стоит сделать параллельно на одной героине, а Live2D рассмотреть как альтернативу с более живым веб-рантаймом.

## 5. Бриф на пробу E-mote: пролог, Мика (если решите пробовать)

### 5.1. Цель

Одна героиня (Мика: больше всего реплик и эмоций), один ракурс, все эмоции пролога. Сравниваем с Rive на одной и той же сцене пролога по трём вещам: живость, вес файла, плавность на телефоне.

### 5.2. Что подготовить вам (организационно)

1. **Лицензия.** Подать заявку на **Indies** (бесплатно при выручке до ¥10 млн): https://emote.mtwo.co.jp/purchase-indies.php. Выбрать **SDK: WebGL (HTML5 Native)**, а не Unity: приложение — React PWA. Форма на японском, при необходимости переведу текст заявки. Для пробы до договора можно бесплатно поработать в えもふり (только чтобы оценить, без коммерческого использования).
2. **Компьютер с Windows** у аниматора (редактор есть только под Windows).
3. **Аниматор** со знанием E-mote. Таких мало, обычно это японские фрилансеры, либо студия M2 (production-услуги на https://emote.mtwo.co.jp/support/).
4. **Шаблон**: стандартный анфас с https://emote.mtwo.co.jp/download/template/. Аниматор скачивает его до начала работы над артом, потому что имена слоёв жёстко заданы шаблоном.
5. После получения SDK — **передать мне** архив WebGL SDK и документацию, и я встрою его в приложение для сравнения.

### 5.3. Арт (художнику)

- **Источник**: только `source/masters/mika.png` (правило `MASTER_REFERENCES.md`). Стиль прежний: чистый контур, плоская заливка, мягкие тени, без текстур и шума.
- **Холст**: 2048 × 3072 (как в брифе 27). Для えもふり предел 2048 × 2048, поэтому в бесплатной пробе — кроп по пояс 2048 × 2048.
- **Поза**: анфас, по пояс до колен, руки опущены и чуть отведены от тела. Телефон в руке **отдельным слоем** (в прологе Мика пока без предмета, но это проверит, как E-mote работает с предметами).
- **Слои — по шаблону E-mote, имена точь-в-точь как в шаблоне** (японские имена; например, `クチ`, а не `口`). Это частая ошибка из FAQ.
- Левый и правый глаз, веки и брови — **одним слоем на обе стороны** (требование E-mote).
- Рамка обрезки (トリミング枠) — залита на 100%.
- **Всё, что закрыто, дорисовано**: шея под волосами, бока под руками, лоб под чёлкой.
- Хвост Мики и резинка — отдельными частями, чтобы работала физика.
- Для поворота головы: эталонные кадры ¾ влево и вправо, как в брифе 27, п. 2.2.

### 5.4. Анимация (аниматору)

Эмоции пролога (и их частота):

| Героиня | Эмоции в прологе |
|---|---|
| Мика | `happy` ×3, `excited` ×1 |
| Рэй | `neutral`, `recorder/neutral`, `smirk` |
| Айрис | `neutral` ×4, `listening` ×2 |

Для пробы — только Мика, но **полный набор эмоций из брифа 27, п. 5.1**: так сравнение с Rive будет честным. Минимум для приёмки — `neutral`, `listening`, `happy`, `excited`, `laugh`, `embarrassed`, `pout`, `thinking`.

Обязательное поведение:
- дыхание и моргание (случайный интервал 2–6 с, иногда двойное);
- **взгляд и поворот головы** по двум осям (−1…1), черты деформируются, а не просто сдвигаются;
- физика хвоста, чёлки и боковых прядей с затуханием; без «желе»;
- рот: раскрытие 0…1 по громкости плюс по возможности формы `a/i/u/e/o` (японский набор гласных в E-mote есть) и `mbp`;
- `talking`: при речи живут брови и голова;
- переход между эмоциями ≤ 150 мс без провалов;
- микродвижение в покое: лёгкое покачивание корпуса, плечи с дыханием;
- реакции одноразовые: кивок, смешок (лёгкая тряска), удивление (подскок), вздох.

### 5.5. Что сдать

- `.emtproj` (исходник), `.emtbytes` (рантайм), исходный PSD;
- `contract.json`: имена переменных и выражений в E-mote и их соответствие нашим именам (`expression`, `mouth`, `talking`, `lookX`, `lookY`, реакции из брифа 27, п. 4);
- видео-превью 1080p с каждой эмоцией, поворотом головы и речью на тёмном и светлом фоне.

### 5.6. Приёмка и сравнение (делаю я)

1. Встраиваю `.emtbytes` через WebGL SDK в отдельную страницу и в сцену пролога (рядом с Rive-версией).
2. Меряю: вес файлов вместе с SDK, время загрузки, FPS на телефоне среднего класса с тремя героинями (цель — 60 к/с), работу офлайн (PWA).
3. Делаю видео «Rive против E-mote» на одной и той же реплике пролога. Решение — за вами.

**Стоп-критерии (если выполняется хотя бы один — от E-mote отказываемся):** WebGL SDK не работает в современных Safari и Chrome на iOS/Android; SDK весит больше ~1,5 МБ; нет возможности управлять выражением и ртом из JS; лицензия требует того, что противоречит PWA или офлайну.

## 6. Что добавить в Rive-риг (бриф 27), чтобы получить «японскую» живость без смены движка

1. **Поворот головы деформацией сетки**, а не сдвигом слоёв: дальняя щека сжимается, нос и рот уходят к краю, контур подбородка меняется. Эталоны — ¾-кадры (бриф 27, п. 2.2). Это главное, что делает Live2D и E-mote «живыми».
2. **Вторичное движение**: волосы и аксессуары с запаздыванием 80–200 мс и затуханием; отдельно на кивок, поворот и смену позы.
3. **Idle-слой**: медленное покачивание корпуса (период 4–7 с), дыхание двигает плечи и грудь, случайные микросаккады глаз каждые 1–3 с, редкий взгляд в сторону.
4. **Кривые**: easing везде (ease-in-out, overshoot 5–10% на кивке и подскоке), без линейных ключей.
5. **Моргание** влияет на брови и щёки (лёгкое сжатие), а при улыбке глаза щурятся.
6. **Сглаженный липсинк**: рот интерполируется между виземами 40–60 мс, без скачков кадров.
7. **Приёмка на прологе**: сцена «Не тот кабинет» с тремя героинями, переключение говорящей с поворотом голов к ней (бриф 27, п. 5.4), запись видео 60 к/с с телефона.
